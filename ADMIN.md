# Админка и база данных

Каталог хранится в **Supabase** (PostgreSQL + хранилище фото). Наличие, цены, новые товары
и фото меняются в **/admin** с телефона — витрина обновляется через несколько секунд после сохранения.

Пока база не подключена или пустая, сайт продолжает работать от Google Таблиц —
переход можно делать спокойно, ничего не ломается.

## 1. Создать базу (один раз, ~10 минут)

1. Зарегистрируйтесь на <https://supabase.com> (бесплатный тариф) → **New project**.
   Регион — ближайший (например, Frankfurt), пароль базы сохраните, он не понадобится сайту.
2. Слева **SQL Editor** → **New query** → вставьте содержимое файла
   [`supabase/schema.sql`](supabase/schema.sql) → **Run**. Создадутся таблицы, защита и бакет `photos` для фото.
3. Скопируйте два значения:
   - **Project URL** — вида `https://abcd1234.supabase.co` (кнопка **Connect** вверху или **Settings → Data API**);
   - **секретный ключ** — **Settings → API Keys**: новый `sb_secret_…` (раздел *Secret keys*, кнопка
     показать/скопировать) или старый **service_role** со вкладки *Legacy API keys*. Подходит любой.
     Никому его не пересылайте.

## 2. Переменные в Vercel

Vercel → проект → **Settings → Environment Variables** → добавьте (для Production и Preview):

| Переменная | Значение |
|---|---|
| `ADMIN_PASSWORD` | Пароль входа в админку, не короче 8 символов |
| `SUPABASE_URL` | Project URL из шага 1.3 |
| `SUPABASE_SERVICE_ROLE_KEY` | секретный ключ из шага 1.3 (`sb_secret_…` или service_role) |

Затем **Deployments → ⋯ у последнего деплоя → Redeploy**.

## 3. Перенести ассортимент

1. Откройте `https://vapetochka.vercel.app/admin`, войдите паролем.
2. Нажмите **Импортировать из таблиц** (или меню ⋯ → «Импорт из таблиц»):
   - **«Импортировать „Общий прайс-лист“»** и **«…„Каменная Горка“»** — забирают всё из Google Таблиц:
     линейки, вкусы, цены, наличие и фото (фото копируются в Supabase и больше не зависят от таблиц).
     Одна точка — до пары минут.
   - Если доступ к таблице закрыт — **Из CSV одного листа**: в таблице лист → Файл → Скачать → CSV,
     указать категорию и точку, загрузить файл. Так по листу за раз.
3. Одинаковые товары из двух таблиц объединяются в одну позицию с отдельным наличием и ценой для
   каждой точки. Повторный импорт ничего не дублирует — он заменяет наличие и цены этой точки.

Полный перенос из Google Таблицы переводит точку в режим «от админки» (см. ниже). Пока точка «от таблицы»,
сайт показывает таблицу с быстрыми правками из админки поверх неё.

## 4. Работа в админке

- **Сверху** — точка (Общий прайс / Каменная Горка): все тумблеры и цены меняются для выбранной точки.
- **Поиск** понимает бренд, линейку и вкус, неправильную раскладку и транслит (как на сайте).
- **Фильтры** — категория, бренд, наличие.
- **Тумблер** справа у вкуса — в наличии / нет. Срабатывает сразу; если связь пропала, вернётся назад и
  покажет ошибку.
- **Название и цену** можно поправить прямо в строке — нажмите на них.
- **⋯ у линейки** — все вкусы в наличии / нет, одна цена на всю линейку, название, бренд, категория,
  фото, удаление.
- **⋯ у вкуса** — название, вариант (0.6 Ом), в каких точках продаётся, своё фото, удаление.
- **Все ✓ / Все ✕** — массово для всех показанных позиций. Например: выберите бренд в фильтре →
  «Все ✕» — весь бренд «нет в наличии».
- **Кнопка +** — новый товар: категория, бренд (из списка или новый), линейка, вкусы (по одному в строке),
  цена, вариант, точки, наличие, фото (с камеры/галереи или ссылкой). Если линейка уже есть — вкусы
  добавятся в неё.
- **Алфавит.** Новый вкус сам встаёт на своё место по алфавиту (эмодзи в начале не учитываются), после
  переименования — тоже. Кнопка **«Вкусы по алфавиту А→Я»** в ⋯ у линейки упорядочивает одну линейку,
  меню ⋯ сверху → **«Все вкусы по алфавиту»** — все сразу.

Изменения появляются на сайте через несколько секунд: после каждого сохранения сайт сам пересобирает
витрину в фоне. Точки «от таблицы» дополнительно обновляются по расписанию каждые 10 минут (см. HOW_TO_UPDATE.md, шаг 4). Покупатели в это время не ждут — им отдаётся предыдущая версия, пока готовится новая.

**Фото с телефона** уменьшаются прямо в браузере перед загрузкой (до 1600 px, обычно 200–500 КБ): так
проходят и снимки новых айфонов (Vercel не принимает файлы больше 4,5 МБ). На витрине фото из хранилища
показываются через `/api/photo` — уменьшенными до размера карточки и с кэшем CDN, поэтому каталог быстро
грузится на телефонах и почти не расходует трафик Supabase.

## Админка и Google Таблицы: два режима точки

Каждая точка работает в одном из режимов (меню ⋯ → **«Таблицы и импорт»**).

**От Google Таблицы** (по умолчанию). База — постоянная копия таблицы: сайт раз в минуту (и при открытии
админки, и по кнопке «Обновить из таблицы») подтягивает изменения таблицы. При этом в админке можно всё:
- **наличие и цены** — «кто изменил последним, тот и прав»: правка из админки держится, пока ту же клетку не
  поменяют в таблице. У изменённой позиции видно «в таблице: …» и кнопка **↺** — вернуть как в таблице;
- **новые вкусы и линейки** — кнопки «+» и «Добавить вкус». Новый вкус встаёт по алфавиту между вкусами
  таблицы, синхронизация его не трогает;
- **фото** — можно поставить своё;
- название, вариант, бренд, категорию и удаление **позиций из таблицы** меняют в таблице (в админке эти поля
  у них закрыты). Добавленное в админке можно менять и удалять здесь.

Новые строки таблицы появляются сами, удалённые из таблицы — пропадают из точки. Если таблица вдруг
прочиталась наполовину пустой, удаление пропускается (защита от случайной очистки).

**От админки.** Кнопка **«Перейти на админку»** — переход мгновенный: всё уже в базе, перед переключением
подтягиваются последние изменения таблицы. Дальше таблица на сайт не влияет. Можно:
- **«Добавить новые из таблицы»** — добавить только то, чего ещё нет (цены и наличие остальных не меняются);
- **«Заменить наличие и цены из таблицы»** — сделать как в таблице;
- **«Вернуть точку на Google Таблицу»** — в любой момент; изменения таблицы за это время придут на сайт,
  добавленное в админке останется.

**CSV одного листа** — если таблица закрыта по ссылке: переключатель «Только новые» / «Заменить всё».

> Для режимов нужна свежая схема базы: выполните **supabase/schema.sql** в Supabase ещё раз
> (повторный запуск безопасен, данные не теряются).

Лист **«ОПТ»** (оптовые цены) пока читается из Google Таблицы, как раньше.

## Новинка!

Метка «✨ Новинка!» показывается на витрине на карточке линейки (в углу фото) или у отдельного вкуса.

- **При добавлении** линейки или вкусов — переключатель «Новинка!» в окне «Новый товар».
- **Для существующих** — круглая кнопка ✨ в строке линейки (нажал — отметил, нажал снова — снял);
  в строке вкуса — нажмите на значок «Новинка» рядом с ним, чтобы снять. В окне линейки и вкуса — переключатель.
- Фильтр «✨ Новинки» в списке — покажет только отмеченное.
- Метка **не затирается** синхронизацией с таблицей: её ставит и снимает только админка.

Метка включается миграцией `supabase/schema.sql` (колонки `is_new`). Пока её нет, админка подскажет обновить базу.

## Резервные копии

- **Автоматически** — раз в сутки (первое обращение после полуночи по Минску) сайт сохраняет весь каталог
  в закрытый бакет `backups` в Supabase, храним последние 30 дней.
- **Вручную** — `https://ВАШ-САЙТ/api/admin/backup` (нужен вход в админку) скачивает файл `.json` со всем
  каталогом: линейки, вкусы, наличие и цены по точкам, режимы точек.
- Одну линейку или вкус проще вернуть из **«Недавно удалённых»** (ниже). Копия за сутки — на случай, если
  нужно откатить много всего сразу: напишите разработчику с датой.

## Недавно удалённые

Меню ⋯ → **«Недавно удалённые»** — всё, что за последние 30 дней удалили в админке или убрали из Google
Таблицы (синхронизацией). Кнопка **«Вернуть»** ставит линейку или вкус обратно — с фото, вариантом, меткой
«Новинка», порядком, ценами и наличием по точкам. Сразу после удаления в админке в уведомлении есть кнопка
«Вернуть» — на случай, если нажали не туда.

- Если ту же линейку или вкус уже добавили заново (например, вписали строку обратно в таблицу), дубля не будет:
  вкусы вернутся в существующую линейку, а уже имеющиеся останутся как есть.
- Возвращённое из таблицы дальше живёт как добавленное в админке: синхронизация его не уберёт снова. Впишете
  строку в таблицу — свяжется с ней сама.
- Пока журнала нет в базе (не выполнен свежий `supabase/schema.sql`), удаление работает как раньше, но вернуть
  удалённое отсюда нельзя.

## Если база не отвечает

- **Обе точки остаются на последней удачной версии витрины**, пока база не вернётся, — и «от админки», и «от
  таблицы». Старую таблицу вместо базы сайт не показывает: в режиме «от админки» она устарела, а в режиме «от
  таблицы» в ней нет вкусов и правок, добавленных в админке.
- Последняя удачная версия — это готовые страницы точек в кэше Vercel (ISR): он общий для всех серверов и не
  пропадает при «холодном старте». Если пересобрать витрину не удалось, Next.js оставляет прежнюю страницу и
  пробует снова при следующем запросе. Если база лежит во время деплоя — деплой не пройдёт, и сайт останется на
  прошлом деплое.
- Лист «ОПТ» сохраняется в кэше: при сбое Google остаётся прошлый оптовый прайс.

## Как это устроено

```
/admin (клиент) ──► /api/admin/*  ──► Supabase REST (service_role, только на сервере)
                        │
                        └─ revalidateTag('catalog') ──► витрина /main, /kamennaya-gorka
```

| Таблица | Что хранит |
|---|---|
| `categories` | Вкладки витрины: id, название, порядок |
| `product_lines` | Линейки: категория, бренд, подраздел, название (с крепостью), пояснение, фото, порядок |
| `items` | Вкусы/позиции линейки: текст (с эмодзи и описанием), вариант, своё фото, порядок |
| `item_stock` | Наличие и цена позиции **в точке**: `(item_id, store_id)`, `price`, `old_price`, `in_stock`. Нет строки — позиции нет в точке |
| `deleted_items` | «Недавно удалённые»: копия удалённой линейки / вкусов с наличием по точкам, 30 дней |

**API** (все роуты, кроме входа, требуют cookie-сессию админки):

| Метод и путь | Что делает |
|---|---|
| `GET/POST/DELETE /api/admin/session` | Статус / вход по паролю / выход |
| `GET /api/admin/catalog` | Весь каталог для админки |
| `PATCH /api/admin/stock` | `{ updates: [{ itemId, storeId, inStock?, price? }] }` — тумблеры, цены, массовые действия |
| `POST /api/admin/items` | Новые вкусы — в существующую линейку (`lineId`) или вместе с новой (`line`) |
| `PATCH/DELETE /api/admin/items/:id` | Изменить / удалить позицию (`title`, `variant`, `imageUrl`, `stores`) |
| `PATCH/DELETE /api/admin/lines/:id` | Изменить / удалить линейку (`name`, `brand`, `categoryId`, `note`, `imageUrl`) |
| `POST /api/admin/upload` | Фото (multipart `file`) → ссылка в Supabase Storage |
| `POST /api/admin/import` | `{ source: "sheets", storeId }` или `{ source: "csv", storeId, category, csv }` |
| `GET /api/admin/trash` | «Недавно удалённые» за 30 дней |
| `POST /api/admin/trash` | `{ id }` — вернуть запись (линейку или вкусы с наличием и ценами) |

**Безопасность.** Пароль проверяется на сервере, сессия — подписанная HttpOnly cookie на 30 дней
(SameSite=Strict — чужие сайты не могут слать запросы от имени админа). Смена `ADMIN_PASSWORD`
завершает все сессии. В базе включён RLS без политик: публичный ключ Supabase ничего не видит, данные
доступны только серверу сайта.
